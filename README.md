# cleanup-shit

一个用于清理历史测试产物的 Codex 技能。旧测试数据库、恢复演练副本或构建缓存占了大量空间时，用它查清哪些东西还在用、哪些可以删，以及删掉以后会失去什么。它默认由两个 AI 会话分工，你负责转发材料，并决定批准哪些删除项。

**仅限非商业使用。** 你可以为自己的非商业项目使用、修改和分享这个技能。分享时请署名、附上许可链接，并说明所做的修改。商业使用须另行取得作者授权。详见 [CC BY-NC 4.0 许可](LICENSE)。

## 使用方法

把本仓库的 `SKILL.md`、`agents/` 目录和 `LICENSE` 复制到目标项目的 `.agents/skills/cleanup-shit/` 下，保留目录结构。然后在该项目的 Codex 会话中描述你想清理的范围。

> $cleanup-shit 帮我调查当前项目里已经结束的恢复演练。生成一份可以转给执行 AI 的调查提示词，列出副本占用、还依赖它们的任务，以及删除后会失去哪些证据。

1. 把设计师给出的提示词转给能访问项目的执行 AI。它调查现场，列出候选路径、依据、预计回收空间和需要保留的材料。
2. 把申请带回设计师会话。设计师复核证据和影响，你按清单编号批准想清理的项，也可以只批准其中一部分。
3. 把针对已批准项的执行指令转给执行 AI，再把执行回执带回。设计师核对实际完成项、失败残留、保留件和可确认的空间收益。

## 为什么默认保留报告

对已经结束的普通开发测试，这个技能默认保留一份能解释测试方法、结果与局限的报告。AI 优先复审已有报告，必要时从现存代码、日志和结果补写摘要，注明证据来源、已知失败和无法确认的事项。清理原始现场后，仍可查阅这些结论，但可能失去原位重演、查阅完整日志或逐文件对账的能力。申请会列明这些取舍，具体删除项由你批准。

项目已有明确留存约定的材料应单独列出。例如，旧实验要求保留逐次测量，就按原约定保留这些数据。唯一业务数据、仍支撑科研结论的原始测量和在用的回归夹具，也应保留。

如果你的项目希望始终保留原始日志，或只对某类测试采用摘要，可以修改 [SKILL.md](SKILL.md) 的“清理判断原则”，再同步更新 [agents/openai.yaml](agents/openai.yaml) 中的 `default_prompt`，让入口提示符合你的留存策略。
